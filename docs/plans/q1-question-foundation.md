# Q1: доверие и основа правил вопросов

**Статус:** выполнено, 2026-09-19. Тип: implementation. Основа — [спецификация вопросов](../specs/question-activity.md), этап [Q1 roadmap](../../GAME_DESIGN.md#1421-активность-вопросы).

## Объём

- Отдельное серверное поле `trust`, начальное значение и ограничения; передача в общем snapshot и сохранение в Prisma repository.
- Чистый расчёт последствий верного/неверного ответа и отказа со стартовым балансом из спецификации.
- Аддитивная SQL-миграция с сохранением существующих данных и финалов.
- Выдача вопросов, попытки, HTTP-команды ответа, история вопросов и окно относятся к Q2. В Q1 расчёт результатов ещё не вызывается существующими действиями ухода.

## Задачи

1. Зафиксировать стартовые допущения баланса в спецификации; добавить `Pet.trust` и поле общего контракта, начальное значение в engine, чтение/запись в mapper и repository.
2. Добавить серверный модуль доверия и чистые правила исходов вопросов; доверие не включать в пять статов, decay и care score.
3. Проверить сборку API, затем обе сборки. На отдельных временных данных проверить исходы и границы, новую/заполненную БД, сохранность истории/финалов, повтор миграции, владение питомцем, параллельные записи и запрет второго активного питомца.
4. Применить проверенную миграцию к локальной БД обычным `db:deploy` с резервной копией и проверкой сохранности записей. Обновить статусы и фактические результаты проверки.

## Ограничения

- Никаких сбросов БД, изменений истории, итогов или баланса существующего ухода.
- Клиент не может передавать/изменять доверие через существующие команды.
- Новые `*.spec.ts` и тестовое покрытие не входят в шаг; проверка — ручной smoke на временной БД.
- Стартовые численные допущения можно скорректировать перед Q2/Q3. Реализация Q1 не означает готовность всей активности.

## Результаты проверки

- Prisma validate/generate, API build и Angular production build прошли; initial bundle 408,20 kB.
- 8 групп ручного smoke на отдельном PostgreSQL 17: исходы и пределы значений, исходный объект не меняется; пустая/заполненная БД, повтор deploy и нулевой schema drift; старые данные семи таблиц и финалы сохранены; SQL отклоняет отрицательное, превышающее максимум и нечисловое доверие.
- Проверены параллельные изменения доверия, изоляция гостя, один активный питомец при пяти параллельных созданиях, сохранение после нового подключения, отсутствие влияния доверия на текущий уход, время и финал.
- HTTP smoke: snapshot содержит `trust: 50`, действующая cookie обязательна, попытки передать `trust` в создание или действие получают `400`.
- Локальная миграция применена после резервной копии в `.local/`. Хеши прежних данных всех семи таблиц совпали; оба существующих питомца получили 50, миграции актуальны, schema drift отсутствует.
- Тестовые базы удалены, отдельный PostgreSQL остановлен. Новое тестовое покрытие не добавлялось и не запускалось.
