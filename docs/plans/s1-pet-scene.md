# S1: сцена питомца

**Статус:** выполнено, 2026-09-20. Тип: implementation и UX. Основа — [спецификация сцены](../specs/pet-scene.md).

1. Добавить вычисляемую сервером доступность действий в transport snapshot, сохранив engine и persistence без новых полей БД.
2. Сделать сцену с SVG-питомцем, состояниями сна/прогулки и иконками действий; подключить подсказки и мобильную карточку.
3. Перенести запуск вопросов на сцену, сохранить существующее окно, реакции и историю. Уплотнить информацию под сценой.
4. Выполнить узкую сборку API, smoke доступности/команд на временных данных, обе сборки и браузерную проверку desktop/mobile. Записать результаты и ограничения.

## Результат

- Новый `PetSceneComponent`: центральная комната, действия по краям, подсказки на hover/focus и мобильная карточка с выполнением. Native disabled блокирует команду; обёртка позволяет узнать причину клавиатурой или касанием.
- SVG-питомец для четырёх доступных видов: дыхание, моргание, закрытые глаза во сне; CSS учитывает `prefers-reduced-motion`. Прогулка показывает пустую сцену и время возвращения, архивная сессия — память и итог.
- `PetSnapshot.actions` вычисляется сервером после resolve в существующей транзакции и не сохраняется. При чтении активного питомца добавляется запрос последней попытки, завершённым питомцам он не нужен. Правила engine, стоимость, cooldown и схема БД не менялись.
- Вопросы запускаются со сцены. Существующие окно, история, реакция, отказ и повтор сохранены; после закрытия фокус возвращается к иконке, включая её заблокированное состояние. Статы компактнее, подробности сессии сворачиваются.

## Проверка

- `npm run build:api` и `npm run check` прошли; `git diff --check` не выявил ошибок пробелов. Новые `*.spec.ts` не добавлялись, тестовый набор не запускался.
- In-memory smoke: все шесть действий сверены с фактическим результатом engine для обычного состояния, сна, прогулки, нулевой энергии, cooldown и ухода. Проверены граница cooldown до/ровно в срок, доступность вопросов после открытия/отказа, ответы команд и polling, отсутствие `actions` в сохранённой записи.
- Восемь одновременных команд дали один успешный `play`; остальные получили cooldown с согласованным snapshot. Проверены чужой pet ID, запрет второго активного питомца и две ожидаемые записи истории ухода.
- Браузер с настоящими Angular/NestJS и изолированным in-memory repository: desktop, 390×844 и 320×740; RU/EN, светлая/тёмная тема. На ширине 320 px кнопки действий около 60×80 px, горизонтального скролла нет.
- Проверены подсказки с клавиатуры и Escape; сон/пробуждение, прогулка, нехватка энергии, архивный итог; запуск вопроса со сцены и через мобильную карточку, верный ответ и отказ по Escape, возврат фокуса. Мобильное кормление применилось один раз и заблокировалось по cooldown; причина доступна по нажатию, обновление сохраняет открытую карточку, закрытие не применяет действие.
- Изображения кошки, собаки и попугая просмотрены в браузере. Динозавр использует ту же SVG-структуру с отдельными силуэтом/цветом; окончательное художественное оформление не входит в S1. Отключение анимации проверено по CSS, системная настройка reduced motion не менялась.
- Браузерная проверка выполнена в локальном preview без PostgreSQL и без изменения пользовательских гостевых cookie/питомцев. Проверка на физическом телефоне и повторная PostgreSQL-проверка не проводились; миграции отсутствуют.
