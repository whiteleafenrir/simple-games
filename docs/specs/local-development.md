# Локальная работа с API и базой

## Решение

Тип задачи: implementation и исправление локального workflow. Игровые правила и схема данных не меняются.

- `npm run dev` подготавливает подключение и Prisma Client, затем запускает Angular, API с перезапуском при изменении TypeScript и Prisma Studio в одном терминале.
- Уже работающий PostgreSQL из `.env` используется без Docker. Docker Compose поднимается автоматически только для стандартного локального подключения из `.env.example`.
- На текущем компьютере PostgreSQL 17 работает как служба `postgresql-x64-17` на порту `5435`; подключение к базе `simple_games` проверено. Локальный `.env` нужно направить на эту существующую базу.
- Swagger по `/api/docs` показывает HTTP-методы и примеры запросов. `/api/health` проверяет API и соединение с БД без изменения игровых данных.
- `npm run dev:doctor` показывает состояние подключения, API, frontend и Studio, не печатая пароль.
- `npm run dev:open` открывает игру, API и таблицы в браузере; отдельные команды позволяют запустить только API или Studio.
- API по умолчанию слушает loopback. Swagger доступен только вне production. Данные, схема и cookie сохраняются при обычном перезапуске.
- Применение схемы не использует `--accept-data-loss` или `--force-reset`. Сброс Docker-базы требует отдельного явно указанного флага и недоступен для стороннего подключения.

## Проверка готовности

1. Запуск на Windows с существующим PostgreSQL без Docker.
2. Сборки Angular и API; Prisma validate/generate.
3. Ответы health, Swagger/OpenAPI и Studio; проксирование `/api` через Angular.
4. Перезапуск API после изменения исходного файла, остановка процессов по Ctrl+C.
5. Понятная диагностика недоступной базы и занятого порта.

Новые `*.spec.ts` не добавляются, существующее покрытие не расширяется. Подробный аудит и инструкция пользователя оформляются отдельно в `docs/`.
