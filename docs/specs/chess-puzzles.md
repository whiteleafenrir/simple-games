# Шахматный модуль и задачи

**Решение, 2026-10-02:** отдельный модуль шахматных правил и экран случайных задач, затем подключение к «Поиграть». Игрок выбирает шахматы среди игр с питомцем и решает задачу вместе с ним. Полноценная партия против питомца — возможное продолжение.

**Статус:** отдельный экран и подключение к играм с питомцем реализованы. Связанный раздел: GDD §11.

## Каталог в БД и сложность, 2026-10-03

**Решение владельца:** подключить готовые открытые задачи, хранить каталог в отдельной таблице и ранжировать по сложности. Старые восемь локальных позиций удаляются из приложения.

**Допущения реализации:** источник — [Lichess Open Database](https://database.lichess.org/#puzzles), лицензия CC0. Стартовый срез содержит 1500 задач: по 500 с рейтингом <1200, 1200–1799 и ≥1800. Это уровни интерфейса «Лёгкие», «Средние», «Сложные»; числовой рейтинг остаётся исходным рейтингом задачи Lichess, а не оценкой игрока. По умолчанию выбран лёгкий уровень. В срез попадают задачи с popularity ≥80, минимум 100 прохождениями и rating deviation ≤100; это фильтр качества, не собственная оценка шахматным движком.

- `ChessPuzzle` хранит id Lichess, исходный FEN, UCI-линию, рейтинг и его отклонение, popularity, число прохождений, темы, ссылку на партию и opening tags. Индекс `(rating, id)` обслуживает выбор по уровню. Каталог общий, без связей с гостем или питомцем.
- Аддитивная миграция создаёт таблицу. `npm run chess:seed` идемпотентно добавляет стартовый CSV из репозитория, не перезаписывая существующие записи; команда входит в `dev:setup`. `npm run chess:import -- --file <CSV или CSV.zst>` позволяет дополнить/обновить каталог потоковым импортом с ограничением числа задач. Большой архив не включается в Git. Импорт проверяет FEN и легальность всей линии через chess.js; ошибочные записи пропускаются с итоговым счётчиком.
- По формату Lichess первый UCI-ход — ход соперника, который нужно применить к FEN до показа доски. Остальные ходы чередуют решение игрока и автоматические ответы соперника. Любой легальный матующий ход принимается как успех, в том числе альтернативный мат в один. Другой неверный ход оставляет текущий шаг без изменений. Подсказка указывает фигуру следующего правильного хода, раскрытие доигрывает оставшуюся линию и получает отдельный исход `revealed`.
- `GET /api/chess/puzzles/random?difficulty=easy|medium|hard&previousId=...` возвращает `{ puzzle }` с нормализованной позицией, решением, рейтингом, темами и ссылкой на источник. Без cookie, без изменения pet state; `Cache-Control: no-store`. Выбор равномерный в уровне, предыдущая задача исключается, если есть другая. Пустой уровень возвращает `{ puzzle: null }`; неверные параметры — `400`.
- UI показывает уровень, рейтинг и источник; поддерживает загрузку, пустой каталог, ошибку и повтор. При ошибке следующей загрузки текущая попытка сохраняется. Запрос ограничен 20 секундами; повторный клик блокируется, ответ после уничтожения компонента игнорируется. Отдельный экран теперь требует API для получения новой задачи. Уже загруженная задача решается локально.
- Хранение попыток, рейтинг игрока, награды и AI-соперник не входят в изменение. Прежний зачёт `play` сохраняется.

**Приёмка:** миграция в изолированной схеме PostgreSQL; повторный seed без дублей; проверки всех импортированных линий, выбора уровней и параметров API, нескольких ходов, ошибок, подсказки, раскрытия и повторного запуска; RU/EN и мобильная доска; lint, форматирование и обе сборки. Постоянные тесты не добавляются.

**Проверка, 2026-10-03:** все 1500 записей прошли импорт с проверкой легальности полной линии. Разовый прогон UI-domain: по 40 задач каждого уровня, 235 ходов игрока, в том числе 51 задача за чёрных и две с превращением; проверены ошибочные ходы без изменения позиции, автоматический ответ, завершение, раскрытие, запрет дальнейшего ввода и альтернативный мат ладьёй вместо ферзя. На изолированной схеме прошли все миграции, повтор deploy, отсутствие drift, повторный seed, сохранение обновлённого рейтинга при seed, upsert, HTTP-выбор каждого уровня без повтора, нормализация FEN, `400`, пустой каталог и единственная задача. Временная схема удалена.

В локальную рабочую БД применена новая миграция и загружены 1500 задач; повторный seed добавил 0 строк. Хеши содержимого всех восьми прежних игровых таблиц до и после совпали. В браузере проверены выигрыш материала в несколько ходов, неверный ход, подсказка, автоматический ответ, самостоятельное решение, просмотр, повтор, три уровня и ориентация за чёрных. RU/EN и тема меняются без сброса задачи; на 320 px нет горизонтального переполнения. Недоступность API сохраняет текущую попытку; повтор после восстановления сервера успешно загружает новую задачу. Повторный зачёт `play` не менялся и отдельно в этом изменении не прогонялся; история решений остаётся вне объёма.

`npm run quality`, финальные lint/format и `git diff --check` прошли; schema drift отсутствует. Разовый прогон потокового чтения проверил служебные и склеенные Zstd frames, подачу по одному байту, некорректную CSV-строку и обрезанный архив. Постоянный тестовый набор не добавлялся.

## Объём первого инкремента (история, 2026-10-02)

- Отдельный маршрут `/games/chess`, доступный по прямой ссылке, и тот же компонент в окне игр с питомцем. Самостоятельный экран не вызывает `play`; запуск из «Поиграть» использует [общий зачёт заботы](pet-activities.md).
- Независимые от Angular функции в `src/app/chess/`: создание позиции из FEN, допустимые ходы, применение/отмена хода, состояние доски, шах, мат, пат и ничья. Правила обеспечивает [chess.js](https://jhlywa.github.io/chess.js/) (BSD-2-Clause); это библиотека правил, без AI-соперника.
- Состояние партии содержит исходную позицию и историю ходов: при восстановлении сохраняется возможность определить повторение позиции. Рокировка, взятие на проходе и все четыре превращения поддерживаются правилами.
- **Допущение инкремента:** восемь локальных составленных позиций «мат в один ход», за белых и чёрных. Нет внешнего сервиса, рейтинга сложности, генератора позиций или загрузки чужого каталога. Новый выбор не повторяет предыдущую задачу подряд.
- Задача решена любым легальным ходом, который действительно ставит мат. Допустимый ход без мата оставляет исходную позицию и предлагает попробовать ещё; нелегальный ход не меняет состояние. Попытки не ограничены.
- Подсказка указывает фигуру, которой можно поставить мат. «Показать решение» выполняет один из подходящих ходов и явно отличается от самостоятельного решения. Можно повторить задачу или выбрать другую.
- Доска ориентирована со стороны решающего. Выбор фигуры/клетки кликом или клавиатурой, подсветка допустимых ходов, отдельный выбор превращения. RU/EN и светлая/тёмная тема.

## Границы и данные первого инкремента (история)

Партия живёт в памяти экрана. Перезагрузка начинает новую задачу. Новых API, таблиц БД, наград и истории решений нет. Внутри игр питомца контейнер применяет существующий `play`, с прежней стоимостью и cooldown; результаты шахматной задачи ничего дополнительно не меняют. Шахматные правила и каталог не зависят от UI, переводов или pet-domain. Обёртка маршрута отвечает только за заголовок и навигацию.

## Точки подключения первого инкремента (история)

- `chess-engine.ts`: `createChessGame(fen?)`, `inspectChessGame(game)`, `playChessMove(game, move)`, `undoChessMove(game)`. Функции возвращают новые значения, не изменяя переданное состояние. Нелегальный ход возвращает отказ; некорректный исходный FEN считается ошибкой вызывающего кода.
- `chess-puzzles.ts`: каталог, случайный выбор без повтора подряд, создание попытки, проверка хода, поиск матующих ходов и раскрытие решения. Результаты `solved` и `revealed` различаются.
- `ChessPuzzleComponent` / `<app-chess-puzzle />`: готовая игра без обращения к питомцу и API. `ChessPageComponent` добавляет заголовок и ссылку домой.
- `PetGamesComponent` встраивает `<app-chess-puzzle class="embedded" />` после своего серверного `play`; класс включает компактную раскладку для диалога. AI-соперник в будущем сможет предлагать ходы для `playChessMove`; принятие такого хода по-прежнему проверяет модуль правил.

## Приёмка первого инкремента (история)

- Каждая позиция имеет хотя бы один легальный матующий ход; исходная позиция не завершена, король ожидающей стороны не находится под шахом.
- Неверный ход не расходует попытку и не изменяет доску; верный завершает задачу. Повторный ввод после завершения не меняет позицию.
- Подсказка, просмотр решения, повтор, смена задачи, выбор превращения и игра за чёрных работают; язык меняется без сброса позиции.
- Самостоятельный экран работает без API; запуск в играх питомца проходит через общий `play`. Нет переполнения на 320 px; фигуры различимы в обеих темах, клетки доступны с клавиатуры и имеют подписи для скринридера.
- Проверка правил и каталога разовым прогоном, frontend build, lint и форматирование. Постоянные тесты и runner не добавляются.

## Проверка отдельного экрана, 2026-10-02

- Разовый локальный прогон: все восемь позиций корректны и имеют решение, найдено девять матующих ходов; в задаче с обычным превращением принимаются и ладья, и ферзь. Проверены отказ после завершения, сохранность исходной позиции при ошибках, раскрытие решения и выбор без немедленного повтора.
- Правила партии: 20 начальных ходов, обе рокировки, запрет рокировки через шах, взятие на проходе и его запрет при раскрытии шаха, четыре превращения с обязательным выбором, отмена хода, трёхкратное повторение, пат, недостаток материала и правило 50 ходов.
- Браузер: легальный ход без мата, нелегальный ход, подсказка, решение за чёрных стрелками и Enter, просмотр решения и перезапуск; превращение в ферзя не решает задачу на коня, отмена выбора работает, `f8=N#` завершает её.
- RU/EN переключаются без сброса позиции; светлая/тёмная тема, экран 320 px без горизонтального переполнения. Настройки и размер браузера после проверки возвращены. Журнал проверенного экрана без ошибок и предупреждений.
- `npm run check` (Prisma Client, API и Angular), `npm run lint`, `npm run format:check` и `git diff --check` проходят. Шахматный экран загружается отдельным chunk около 54 kB; начальный bundle остаётся в бюджете 500 kB.
- Интеграция с питомцем и полный шахматный соперник не реализованы и не проверялись. Постоянные автотесты не добавлялись.
