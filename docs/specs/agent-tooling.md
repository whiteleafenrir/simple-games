# Инструменты разработки с ИИ

**Решение владельца, 2026-09-27. Тип:** developer tooling и актуализация контекста. Игровое поведение не меняется.

## Объём

- Короткая карта задач в `docs/ai/README.md` направляет к действующим спецификациям, коду и проверкам. GDD хранит продуктовые решения, focused specs — подробные правила; отчёты фиксируют исторические результаты проверки.
- Устаревшие тесты, их неиспользуемый in-memory repository и отдельная конфигурация Vitest удаляются. Автотесты остаются отдельной задачей после стабилизации UX и правил; lint не меняет это решение.
- ESLint проверяет TypeScript и служебный JavaScript, включая границы frontend/API/общего контракта. Строгая компиляция остаётся отдельной проверкой.
- Prettier применяется постепенно к новым и изменённым поддерживаемым файлам. Локально учитываются staged, unstaged и untracked файлы; CI сравнивает с базой PR или предыдущим состоянием push. Для нового branch push и ручного запуска проверяется последний коммит. Полное форматирование старого кода не входит в задачу.
- `npm run check` сохраняет назначение проверки сборок. `npm run quality` объединяет lint, проверку форматирования и сборки; CI запускает эти проверки без тестов.
- Проектные скиллы `pocket-pet-verify` и `pocket-pet-review` помогают при выбранной задаче проверки/ревью. Они не вводят новый обязательный этап приёмки владельцем и не требуют запускать весь список сценариев после каждой правки.
- Angular MCP использует установленный Angular CLI, режим `--read-only` и только инструменты документации/обзора проекта. Настройка хранится в проекте; личные настройки Codex не заменяются.

## Отложено

Наборы игровых состояний и управление временем для проверки записываются в roadmap после стабилизации продукта. В этой задаче не создаются fixtures, seed-команды, debug API или новый тестовый набор.

## Порядок и приёмка

1. Обновить контекст и roadmap, удалить устаревший тестовый контур.
2. Добавить lint/format и CI; исправить обнаруженные статические замечания без изменения gameplay.
3. Создать и валидировать два скилла; подключить MCP и проверить его запуск и чтение workspace.
4. Выполнить `npm run quality`, проверить выбор файлов formatter и срабатывание ограничений импортов. Проверка сборок не применяет миграции к пользовательской БД.

## Использование

- `npm run lint` — статический анализ всего исходного кода и скриптов.
- `npm run format:check` — форматирование изменённых файлов без записи.
- `npm run format` — форматирование этих же файлов с записью; не меняет Git index.
- `npm run format:check -- --base <commit>` — проверка файлов, отличающихся от указанного коммита, включая текущие локальные правки.
- `npm run format:check -- --all` — необязательный аудит форматирования всего репозитория; старые файлы ещё могут не соответствовать Prettier.
- `npm run quality` — lint, форматирование локальных изменений и обе сборки.

Конфигурации: `eslint.config.mjs`, `.prettierrc.json`, `.prettierignore`, `.codex/config.toml`. Сгенерированные файлы, lockfile, `.env`, временные данные и старые SQL migrations не форматируются.

## Выполненная проверка, 2026-09-27

- `npm run quality` прошёл: ESLint, Prettier изменённых файлов, генерация Prisma Client, API и Angular production build. Миграции и игровые запросы не выполнялись.
- Отдельными временными пробами проверены запреты импортов frontend/API/контракта и допустимый импорт общих типов. В изолированном временном Git-репозитории проверены выбор formatter (staged/unstaged/untracked, имена с пробелами и Unicode, ignore, rename/delete), `--base`, первый push с нулевым SHA, режим `--all`, ошибки аргументов и сохранность index.
- Единственная правка существующего runtime-файла — форматирование `prisma-pocket-pet.repository.ts`, включая перенос tagged template. Нормализованный скомпилированный JavaScript до/после совпадает; версии ранее установленных пакетов в lockfile не изменились.
- Оба `SKILL.md` прошли валидатор skill-creator. Поведение скиллов в отдельной игровой задаче пока не проверялось.
- Пользовательский Codex видит MCP `angular` как включённый. Реальное stdio-подключение из корня и `src/app` нашло workspace/Angular 22; `get_best_practices` вернул руководство, `search_documentation` — результаты из индекса версии 22. В изолированном shell `codex mcp get` не всегда видит пользовательскую регистрацию; проверка выполнена также вне sandbox. Для текущего интерфейса Codex требуется обновление подключения MCP.
- Постоянные автотесты не добавлялись и не запускались. Обновлённый GitHub Actions workflow проверен локально по конфигурации; удалённый запуск требует push.
